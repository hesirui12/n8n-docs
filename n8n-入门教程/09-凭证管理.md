## 1. 凭证是什么 / What Are Credentials?

> **官方原文**：Credentials are securely stored authentication information used to connect n8n workflows to external services such as APIs, or databases.
> **翻译**：凭证是安全存储的认证信息，用来把 n8n 工作流连接到外部服务（如 API、数据库）。

**大白话**：凭证 = 一把把「钥匙」。连接 Gmail、NASA API、数据库都要钥匙（账号密码、API Key、OAuth 授权）。n8n 会把钥匙**加密保管**，绝不写进工作流 JSON 里——导出/分享工作流时钥匙不会跟着走（第 16 章讲 n8n packages 时再展开）。

> ⚠️ **安全红线**：不要把 API Key、密码发到聊天里、贴进截图、写进博客。凭证只在 n8n 的凭证界面里输入。

## 2. 创建凭证的三种入口 / How to Create

| 入口 | 操作 |
|------|------|
| **侧边菜单 + 按钮** | 左侧菜单左上角的 **Create（+）** 按钮 → Credential → 选择应用/服务 |
| **概览页 + 按钮** | Overview 页面右上角 **Create** → Credential |
| **节点设置里** | 编辑节点时，在「Credential for XXX」下拉框里选 **Create new credential**（第 03 章就是这么做的） |

**流程**：选服务 → 填服务要求的字段（可参考官方「凭据库」`integrations/builtin/credentials/` 的说明）→ **Save 时 n8n 会自动测试**，测不过会报错提示你检查。

> 💡 **命名建议**：n8n 默认命名「节点名 account」，建议改成「服务 - 用途」风格，如 `gmail-客服自动回复`、`nasa-太阳耀斑`。团队里找钥匙全靠好名字。

## 3. 凭证类型 / Credential Types

创建/编辑 **OAuth 类型**凭证时，可以选择：

| 类型 | 行为 | 适合 |
|------|------|------|
| **Fixed credential（固定凭证）** | 不管谁运行工作流，都用这同一个账号 | 默认，大多数场景 |
| **End-user credential（终端用户凭证）** | 运行时用**触发者本人**的账号；每个人只能看到/使用自己的 | 企业里「各人连各人的 Google 日历」这类场景（Enterprise 计划） |

> 💡 **小白理解**：固定凭证 = 公司公用钥匙；终端用户凭证 = 每人拿自己的钥匙开门，互不可见。

## 4. Allowed HTTP Request Domains / 允许的请求域名

很多 Web API 类凭证里有这个字段，控制该凭证**能否在 HTTP Request 节点里对指定域名使用**：

| 选项 | 效果 |
|------|------|
| **All** | 任何 URL 都能用这个凭证（有被滥发到陌生域名的风险） |
| **Specific Domains** | 只允许列出的域名，如 `api.github.com, httpbin.org` |
| **None** | 彻底禁止在 HTTP Request 节点使用（只在自己的专属节点里生效） |

> 💡 **安全价值**：防止你的 Key 被某个工作流误发到不属于它的网站（凭证外泄的常见事故）。**默认建议选 Specific Domains。**

## 5. 在凭证里用表达式 / Expressions in Credentials

有些服务的令牌（access token）会随每次请求变化，可以在凭证字段里填**表达式**动态取值：

1. 找到工作流里存有该令牌的数据（比如 Webhook 收到的 `Authorization` 头）。
2. 创建凭证时，鼠标悬停目标字段 → 打开 **Expression** 开关。
3. 填表达式，如 `{{ $json.body.access_token }}` 或 `{{ $('Webhook').item.json.headers.authorization }}`。

> 官方原文：Each workflow execution has its own data context. Expressions are evaluated per execution, so different executions don't share data.
> 翻译：每次工作流执行都有自己的数据上下文。表达式按执行求值，不同执行之间不共享数据。

## 6. 团队协作：凭证共享 / Sharing Credentials

> 官方出处：`docs/administer/manage-credentials/share-credentials-securely.md`

| 场景 | 做法 |
|------|------|
| 想把工作流分享给同事，但不想暴露钥匙 | 共享**工作流**即可；同事能用但**看不到钥匙本身** |
| 同事要编辑用了你凭证的节点 | 需要把**凭证共享**给他，否则那部分节点他只能看不能改 |
| 想批量管理 | 管理员/所有者可以管理全实例凭证；也可以用**外部密钥库**（External Secret Stores，Enterprise）对接 Vault 等 |

> ⚠️ **最小权限原则**：n8n 的共享是「least privilege」——没共享凭证时，收到分享工作流的人**不能编辑**用到该凭证的节点，但可以查看和执行整个工作流。

## 7. 凭证覆盖与外部密钥库 / Advanced (Enterprise)

- **Credential overwrites（凭证覆盖）**：管理员可以用环境变量/配置文件**覆盖**节点里引用的凭证，用于多环境切换（dev/test/prod 各一把钥匙）。
- **External secret stores（外部密钥库）**：把凭证密钥存到 HashiCorp Vault、AWS Secrets Manager 等，n8n 运行时去取（Enterprise 功能）。

> 💡 这两个是企业级功能，新手了解存在即可。

---

## 8. 一句话总结 / TL;DR

```
创建：节点设置里选 Create new credential → 填 Key → Save（自动测试）
命名：服务-用途，方便团队找
安全：凭证加密存储；导出/分享工作流不带钥匙；慎选 Allowed Domains=All
动态：令牌会变的用表达式填凭证字段
分享：共享工作流 ≠ 共享钥匙；要同事能改节点才共享凭证
```
