## 1. 自部署方式对比 / Self-hosted Options

| 方式 | 适合 | 要求 |
|------|------|------|
| **npm** | 本地开发、单机测试 | Node.js **20.19 ~ 24.x** |
| **Docker** | 大多数自部署场景（官方推荐） | Docker Desktop / Engine |
| **Docker Compose** | 生产环境、多容器（加数据库等） | Docker + Compose |
| **AI Starter Kit** | 想快速搭 AI 应用栈 | Docker Compose |

> **官方原文**：n8n recommends using Docker for most self-hosting needs. It provides a clean, isolated environment.
> **翻译**：n8n 推荐大多数自部署场景使用 Docker，它提供干净、隔离的环境。

**npm 快速上手**（升级版，注意 Node 版本要求）：

```bash
npx n8n                 # 不安装直接试
# 或
npm install n8n -g      # 全局安装
n8n start               # 启动
```

**Docker 标准启动命令**（第 02 章的完整版，官方原文）：

```bash
docker volume create n8n_data

docker run -it --rm \
 --name n8n \
 -p 5678:5678 \
 -e GENERIC_TIMEZONE="Asia/Shanghai" \
 -e TZ="Asia/Shanghai" \
 -e N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true \
 -v n8n_data:/home/node/.n8n \
 docker.n8n.io/n8nio/n8n
```

> ⚠️ **任务运行器（Task Runners）**：从 2.0 起默认开启，**不需要**再设 `N8N_RUNNERS_ENABLED=true`（1.x 才需要）。它是 n8n 推荐的任务执行方式。

**Docker Compose / AI Starter Kit**：官方维护的 [n8n-hosting 仓库](https://github.com/n8n-io/n8n-hosting) 提供各种架构的 docker-compose 文件（withPostgres、withQdrant 等）。AI Starter Kit 一键拉起 **n8n + PostgreSQL + Qdrant**，做 AI 工作流最省心。

## 2. 数据库 / Database

| 数据库 | 默认？ | 说明 |
|--------|--------|------|
| **SQLite** | ✅ 默认 | 零配置，单文件，适合学习和中小负载 |
| **PostgreSQL** | 可配 | 生产推荐：用环境变量 `DB_TYPE=postgresdb` + `DB_POSTGRESDB_*` 系列配置 |

> ⚠️ 即便用 PostgreSQL，`/home/node/.n8n` 目录也建议挂持久卷——里面还有**加密密钥、实例日志、源码控制资产**等重要数据。

## 3. 环境变量必配项 / Key Environment Variables

> 官方出处：`configure-n8n/manage-settings-using-environment-variables.md`（完整清单在 `deploy/host-n8n/configure-n8n/basic-configuration/use-environment-variables/`）

| 环境变量 | 作用 | 新手建议 |
|---------|------|---------|
| `GENERIC_TIMEZONE` | 定时触发器时区 | `Asia/Shanghai` ⭐ |
| `TZ` | 容器系统时区 | `Asia/Shanghai` ⭐ |
| `N8N_PORT` | 端口（默认 5678） | 冲突时改 |
| `N8N_ENCRYPTION_KEY` | 凭据加密密钥 | 生产环境必须固定，否则重启后凭据可能失效 |
| `N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS` | 配置文件权限加固 | 官方默认命令里已带 |
| `DB_TYPE` / `DB_POSTGRESDB_*` | PostgreSQL 连接 | 用 PG 时配 |
| `N8N_ENABLED_MODULES` | 启用模块（如 agents） | 尝鲜 agents 时加 `agents` |

> 💡 自部署设置界面的 **Settings** 里也能改大部分配置，但环境变量适合容器化和多环境（dev/prod 区分）。

## 4. 升级与迁移 / Updating & Migrating

**Docker 升级**：

```bash
docker pull docker.n8n.io/n8nio/n8n        # 拉最新稳定版（可指定 :1.81.0 之类版本号）
docker stop <容器ID> && docker rm <容器ID>  # 停旧容器
docker run --name=n8n [之前的参数] -d docker.n8n.io/n8nio/n8n
```

**npm 升级**：`npm update -g n8n`

> ⚠️ **大版本迁移指南**：升级前查官方 `docs/changelog/`——v1→v2、v2→v3 等都有**破坏性变更清单 + 迁移工具**（如 `v20-migration-tool.md`）。**先备份**（导出工作流 + 数据卷快照）再升级。

## 5. n8n Cloud / n8n Cloud

> 官方出处：`docs/deploy/use-n8n-cloud/`

| 事项 | 说明 |
|------|------|
| **免费试用** | 新用户可开 14 天试用（含 Pro 功能） |
| **更新** | Cloud 由 n8n 官方自动维护升级 |
| **管理员后台** | 管理成员、计划、用量 |
| **并发限制** | 生产执行有并发上限（按计划档位），超出排队（FIFO 先进先出） |
| **执行配额** | 生产执行计入每月配额（第 07 章讲过） |

> 💡 **并发是什么**：同一时刻最多有多少个工作流在跑。排队中的任务在「可用名额」释放后自动执行。手动执行、子工作流、错误工作流**不占**生产并发。

## 6. 版本对比 / Community vs Business vs Enterprise

> 官方出处：`deploy/host-n8n/community-edition-features.md`

| | **Community（社区版）** | **Business（商业版）** | **Enterprise（企业版）** |
|--|----------------------|----------------------|------------------------|
| 费用 | 免费 | 付费 | 付费 |
| 核心功能（400+ 节点、AI、全部基础能力） | ✅ | ✅ | ✅ |
| 用户管理/项目 | 基础 | ✅ | ✅ |
| 分享/团队协作 | 受限 | ✅ | ✅ |
| SSO（SAML/LDAP）、源码控制、多环境 | ❌ | 部分 | ✅ |
| 支持 | 社区 | 官方支持 | 官方支持 + SLA |

> 💡 **自部署无许可密钥 = 社区版**。个人使用、学习、小团队，社区版完全够。

## 7. 运维三件套 / Operate: Logs, Monitoring & CLI

| 工具 | 干什么 | 官方章节 |
|------|--------|---------|
| **日志（Logging）** | 输出结构化日志（文件/控制台/Sentry 等） | `keep-n8n-running/set-up-logging.md` |
| **监控（Monitoring）** | 指标 + Prometheus + Grafana 可视化 | `keep-n8n-running/monitor-n8n.md`、`visualize-metrics-with-grafana.md` |
| **CLI** | 命令行管理：导出导入工作流/凭据、健康检查 | `configure-n8n/use-the-command-line.md`（第 16 章详讲） |

常用 CLI 命令预览：

```bash
n8n export:workflow --all --output=./backup/     # 备份所有工作流
n8n import:workflow --input=./backup/workflows.json  # 导入
n8n start                                        # 启动
```

> 💡 **新手建议**：个人自部署做到「数据卷持久化 + 定期 CLI 备份导出」就够了；团队上生产再上监控和日志流。

## 8. 架构速览（了解即可）/ Architecture

> 官方出处：`understand-the-architecture/how-n8n-works.md`

- **单机模式**：一个进程跑全部（默认，够用）
- **队列模式（Queue Mode）**：主进程 + 多个 worker，横向扩容，处理高并发（Enterprise/Cloud Enterprise）
- **数据库**：工作流、执行、凭据都存在数据库里（SQLite/Postgres）

## 9. 一句话总结 / TL;DR

```
个人：Docker（+数据卷）或 npm，记得设 Asia/Shanghai 时区
生产：Docker Compose + PostgreSQL + 固定 N8N_ENCRYPTION_KEY + 定期备份
升级：先看 changelog 迁移指南，先备份再动手
Cloud：免运维但有并发/配额；自部署完全可控
版本：社区版免费够用；要 SSO/多环境再上 Business/Enterprise
```
