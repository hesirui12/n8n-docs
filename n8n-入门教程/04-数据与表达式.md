## 1. n8n 的数据结构 / How n8n Structures Data

> **官方原文**：In n8n, all data passed between nodes is an array of objects.
> **翻译**：在 n8n 中，节点之间传递的所有数据都是「对象的数组」。

听起来很吓人？其实很简单。**JSON** 是一种通用的文本数据格式，长这样：

```json
[
  {
    "姓名": "小明",
    "年龄": 18,
    "城市": "上海"
  },
  {
    "姓名": "小红",
    "年龄": 20,
    "城市": "北京"
  }
]
```

- `[ ]` 表示**数组**（一组数据，可以有很多条）
- `{ }` 表示**对象**（一条数据，包含若干「键值对」）
- `"姓名": "小明"` 就是一条**键值对**：字段名（key）叫"姓名"，值（value）是"小明"

### n8n 数据结构的官方格式

n8n 在每个数据项外面还包了一层 `json` 键（特殊场景还有 `binary` 键放文件、图片等二进制数据）：

```json
[
  {
    "json": {
      "姓名": "小明",
      "年龄": 18
    }
  },
  {
    "json": {
      "姓名": "小红",
      "年龄": 20
    }
  }
]
```

> 💡 **小白提示**：你在界面上看到的 INPUT/OUTPUT 面板，展示的就是这种数据结构。NASA 节点返回的每条数据里就有 `classType`、`beginTime` 等字段——第 03 章你拖拽的 `classType` 就是这个结构里的一个键。

### 数据怎么流动 / How Data Flows

> **官方原文**：When you connect nodes in a workflow, data automatically passes from one node to the next. Nodes process multiple items automatically.
> **翻译**：当你连接节点后，数据自动从一个节点传到下一个。节点会自动处理多条数据项。

**要点**：

1. 数据沿连线自动流动，不需要手动搬运。
2. 上游节点有 3 条数据，下游节点就会**逐条处理 3 次**（比如创建 3 张卡片、发 3 封邮件）。
3. 上一个节点的输出 = 下一个节点的输入。

## 2. 什么是表达式？/ What Are Expressions?

> **官方原文**：Expressions allow you to populate node parameters dynamically by executing JavaScript code. Instead of providing a static value, you can use the n8n expression syntax to define the value using data from previous nodes.
> **翻译**：表达式允许你通过执行 JavaScript 代码动态填充节点参数。你不需要提供固定值，而是可以用表达式语法，根据前一个节点的数据来定义值。

**大白话**：表达式就是「自动填值」。两种对比：

| 方式 | 写法 | 结果 |
|------|------|------|
| 固定值 | 填 `X1.2` | 永远显示 X1.2 |
| 表达式 | `{{$json["classType"]}}` | 每次运行时自动取当前数据的 classType 值 |

### 表达式的三种写法（由简到繁）

**写法 1：点语法（推荐新手）**

```js
{{ $json.城市 }}
```

取当前数据里 `城市` 字段的值。上一章你拖拽生成的 `{{$json["classType"]}}` 和这个是等价的。

**写法 2：方括号语法**

```js
{{ $json["城市"] }}
```

和写法 1 效果一样，字段名带特殊字符（空格、横杠等）时必须用这种。

**写法 3：嵌套字段**

如果数据是嵌套的（字段里还有字段）：

```js
{{ $json.body.city }}
```

> **官方示例**：Webhook 收到的数据里有个 `body` 对象包含 `city` 字段，用 `{{$json.body.city}}` 就能取出城市名。
> 官方原文：This expression: 1. Accesses the incoming JSON-formatted data using n8n's custom `$json` variable. 2. Finds the value of `city`.
> 翻译：这个表达式：1. 通过 n8n 的 `$json` 变量访问传入的 JSON 数据；2. 找到 `city` 的值。

### 关键内置变量速查 / Key Built-in Variables

| 变量 | 含义 | 示例 |
|------|------|------|
| `$json` | 当前节点收到的数据 | `{{ $json.字段名 }}` |
| `$now` | 当前时间 | `{{ $now }}` |
| `$today` | 今天日期 | `{{ $today.minus(7, 'days') }}`（第 03 章用过） |
| `$("节点名")` | 指定节点的数据 | `{{ $('NASA').item.json.classType }}` |
| `$env` | 环境变量 | `{{ $env.变量名 }}` |
| `$vars` | 自定义变量（第 11 章详讲） | `{{ $vars.我的变量 }}` |

## 3. 新手最省力的技巧：拖拽 / The Easiest Way: Drag & Drop

**不需要背语法！** 官方推荐的做法是**拖拽**：

1. 打开节点设置，鼠标悬停在某个输入框上，会出现 **Expression（表达式）** 选项卡。
2. 切换到 Expression 选项卡，点展开按钮打开完整表达式编辑器。
3. 左侧/下方是 **INPUT（输入）面板**，显示上一节点的数据。
4. **直接把想要的字段拖进编辑器**，n8n 自动生成正确的表达式引用。

> 官方原文：You can map `fruit` by dragging and dropping **fruit** from the **INPUT** into the field where you want to use its value. This creates an expression, `{{ $json.fruit }}`.
> 翻译：你可以把 INPUT 面板里的字段拖拽到你想要使用其值的位置，这会生成一个表达式 `{{ $json.fruit }}`。

## 4. 数据转换的最佳实践 / Best Practice: Transform Data with Edit Fields

官方明确建议：**不要**在多个节点里写复杂表达式，而是先用专门的数据处理节点整理好数据。

> **官方原文**：If your main goal is to transform data using expressions without performing any other operations, use the **Edit Fields (Set)** node. This node is designed specifically for data transformation, providing a clean interface to: Add new fields with expression-based values; Modify existing field values; Remove or rename fields. **Best practice**: Instead of adding complex expressions to multiple parameters across different nodes, use Edit Fields to prepare your data first.
> **翻译**：如果你主要想用表达式转换数据，请使用 **Edit Fields（编辑字段/Set）节点**。它专为数据转换设计，界面清爽，可以：添加基于表达式的新字段、修改现有字段值、删除或重命名字段。**最佳实践**：不要在多个节点里堆复杂表达式，先用 Edit Fields 把数据准备好，再传给后续节点。

**新手速记**：「取数 → Edit Fields 整理 → 下游使用」是一条健康的工作流结构。

## 5. 数据固定与模拟 / Pin & Mock Data（开发期两大法宝）

开发工作流时，你往往不想反复请求外部系统、也不想被真实数据干扰。n8n 提供两个配套功能：

| 功能 | 中文 | 作用 |
|------|------|------|
| **Data Mocking** | 数据模拟 | 造一份「假数据」来测试逻辑，不用连真实数据源 |
| **Data Pinning** | 数据固定 | 把（模拟的或真实的）测试数据**存起来**，以后每次执行都用这份，不再去抓新数据 |

> 官方原文：Both approaches save time and resources during development, help you work with consistent datasets, and protect live systems from repeated test calls.
> 翻译：两种方法都能在开发期节省时间和资源、让测试数据集保持一致，还能保护线上系统不被反复测试调用打扰。
>
> ⚠️ **注意**：这些是**开发专用**功能，**生产执行会自动忽略所有固定的数据**。

### 怎么造模拟数据（Mock）？

| 方法 | 怎么做 | 适合 |
|------|--------|------|
| **Edit Fields 节点** | 添加字段 → 填自定义值 | 小规模测试 |
| **Code 节点** | 用 JavaScript 生成任意数据集 | 复杂/边界情况 |
| **Customer Datastore 节点** | 内置假客户数据集，执行即可看 | 纯探索 n8n 时 |

### 怎么固定数据（Pin）？

1. 运行节点，让它把数据拉回来（或先造好模拟数据）。
2. 在节点的 **OUTPUT（输出）** 面板，切换到 **JSON** 视图。
3. 点 **Edit（编辑）** 可以手改数据（用来构造边界场景），点固定图标（或快捷键 `P`）即可固定。
4. 之后每次运行，n8n 直接用这份固定数据，不再请求外部服务。想解除就点面板顶部的 **Unpin** 横幅。

> 💡 **小白场景**：你搭的「天气播报」工作流依赖外部 API，调试邮件排版时每次都要等 API 返回？**Pin 住数据**，改邮件节点时秒级测试，最后发布前记得 Unpin（生产环境本来就会忽略）。

## 6. 筛选数据 / Filtering Data

n8n 里「筛选」有两层意思，别搞混：

### 6.1 界面可视化筛选（不改数据）

在节点 INPUT/OUTPUT 面板顶部点 **Search**，输入关键词即可过滤显示。**纯视觉**，不改变、不删除数据，关掉节点就重置。

### 6.2 工作流运行中真实筛选（改数据）

| 想干什么 | 用哪个节点 |
|---------|-----------|
| 只保留满足条件的**整条数据** | **Filter（筛选）节点** |
| 去掉对象里的**某些字段**（保留条目本身） | **Edit Fields（Set）节点**，配置为删除字段 |
| 过滤数组内部元素（字段里的列表） | 表达式 `.filter()` 方法，如 `{{ $json.myArray.filter(item => item.value > 10) }}` |
| 去掉历史执行里见过的**重复数据** | **Remove Duplicates（去重）节点** |

> 💡 **小白区分**：`If` 是「分流」（真/假两条路都保留），`Filter` 是「筛掉」（不满足的整条丢弃）。按需选择。

## 7. 数据表（Data Tables）/ Data Tables

> **官方出处**：`docs/build/work-with-data/data-tables.md`

**Data Tables（数据表）** 是 n8n 内置的「小数据库」，让你**不用搭外部数据库**就能在工作流里保存、管理、查询结构化数据。适合：

- 跨工作流持久化数据（同一个项目里）
- 存标记防止重复运行（去重游标）
- 跨工作流复用提示词/消息
- 存 AI 评测数据、工作流运行结果
- 做查询表（lookup table）

**三种操作方式**：

| 方式 | 说明 |
|------|------|
| **Data Table 节点** | 在工作流里自动增删改查（创建、读取、更新、删除） |
| **Data tables 选项卡** | 在项目里可视化建表、导 CSV、编辑行列 |
| **DataTable API** | 用 n8n API 的 `/datatables` 端点编程操作（进阶） |

**新手最快上手**：项目页点 **Data tables** 选项卡 → 右上角 **Create Data table** → 选「从零建表」或「导入 CSV」。

> ⚠️ **限制速览**：默认实例总存储上限 200 MiB（自部署可用环境变量 `N8N_DATA_TABLES_MAX_SIZE_BYTES` 调整）；数据表**属于项目**，跨项目不行（想跨项目用 Variables 变量）。

### 数据表 vs 变量 / Data Tables vs Variables

| 能力 | Data Tables | Variables |
|------|------------|-----------|
| 表格视图、行列结构 | ✅ | ✗ |
| 跨项目访问 | ✗ | ✅ |
| 适合存长结构化数据 | ✅ | ✗（值上限 1000 字符） |
| 在表达式里直接取用 | ✗ | ✅ |

## 9. 表达式常见报错与解决 / Common Expression Errors

以下内容翻译整理自官方手册「Common issues」小节，都是新手高频坑：

### 9.1 "Can't get data for expression"（无法获取表达式数据）

- **原因**：表达式引用的上一个节点**还没执行过**，没有数据可取。
- **解决**：先执行（Execute step）那个被引用的节点，再回来测试当前节点。
- **变体**：报错提示 `An expression references the node '<node-name>', but it hasn't been executed yet`——意思完全一样：先执行 `<node-name>` 这个节点。

### 9.2 "The 'JSON Output' in item 0 contains invalid JSON"（JSON 输出无效）

- **原因**：在 JSON 模式里填了不是合法 JSON 的内容；或引用了并不存在的字段。
- **解决**：用 <https://jsonlint.com/> 校验 JSON 格式；确认引用的字段在输入数据里真实存在。

### 9.3 "Invalid syntax"（语法无效）

- **原因**：表达式有拼写/标点错误，比如多了个句点 `{{ $('If').item.json. }}`。
- **解决**：对照第 2 节的写法检查，或删掉重新拖拽生成。

> 💡 **小白口诀**：表达式报错 → ① 上一节点跑了没？② 字段名打错没？③ 直接用拖拽重做一遍。

## 10. 进阶技巧（了解即可）/ Advanced Tips (Optional)

- **长表达式**：想写多行 JavaScript 逻辑，需要包上 IIFE 语法 `{{(()=>{ ... })()}}`——新手可以先跳过（第 11 章有完整例子）。
- **三元运算符**：表达式里直接写条件，如 `{{ $json.age >= 18 ? '成年' : '未成年' }}`。
- **在凭据里用表达式**：有些服务的 access token 会随每次请求变化，可以在凭据字段里填表达式动态取值（第 09 章详讲）。
- **Code 节点**：需要更复杂处理时用 Code 节点写 JavaScript（第 11 章）。
