## 1. AI 工作流长什么样 / AI Workflow Structure

n8n 的 AI 节点是**「根节点 + 子节点」**的集群结构（Cluster Nodes）：

```
[Chat Trigger] ──→ [AI Agent] ──→ [回复]
                     ├─ OpenAI Chat Model（大模型）
                     ├─ Simple Memory（记忆）
                     └─ HTTP Request Tool（工具）
```

| 角色 | 节点类型 | 干什么 |
|------|---------|--------|
| **根节点** | AI Agent / Basic LLM Chain / 向量库等 | 工作流里的「大脑」 |
| **子节点** | 模型 / 记忆 / 工具 / 检索器 | 给根节点提供能力，从左侧插进根节点 |

**支持的模型供应商**：OpenAI、Anthropic、Google Gemini、以及数百个其他 LLM 供应商（官方在 `integrations/builtin/cluster-nodes/` 有完整列表）。

> 🌏 **本土化提示**：如果 OpenAI/Anthropic 访问或支付不便，n8n 支持**国内可直连的模型**：阿里云百炼（Qwen）、DeepSeek、Moonshot（Kimi）、智谱 GLM 等都有对应的 LangChain/OpenAI 兼容端点，按「OpenAI Chat Model + 自定义 Base URL」或对应节点配置即可。

## 2. Agent vs Chain / Agents vs Chains

> **官方原文**：One way to think of an agent is as a chain that knows how to make decisions. Where a chain follows a predetermined sequence of calls to different AI components, an agent uses a language model to determine which actions to take.
> **翻译**：可以把 Agent 理解为「会做决策的 Chain」。Chain 按预设顺序调用组件；Agent 用大模型决定下一步该做什么。

| | **Chain（链）** | **Agent（代理）** |
|--|----------------|-------------------|
| 行为 | 固定流程：问 → 答 | 自主决策：问 → 选工具 → 看结果 → 再决定 |
| 记忆 | ❌ 不支持 | ✅ 支持（Simple Memory 等） |
| 工具 | ❌ 不支持 | ✅ 支持（可调用外部工具） |
| n8n 节点 | Basic LLM Chain、Question and Answer Chain、Summarization Chain | AI Agent（一个节点多种类型） |

**什么时候用谁**：

- 固定任务（翻译、摘要、分类）→ **Chain** 简单可靠
- 需要查资料、调 API、多轮对话 → **Agent**

> 💡 **官方示例**：问「猫」→ 对 chain 说它会照模板答；对 agent 说它会去查 Wikipedia 再答。同一个模板工作流 `docs/_workflows/advanced-ai/examples/agents_vs_chains.json` 可以导入体验。

## 3. 记忆 / Memory

> **官方原文**：The memory keeps a history of previous messages, allowing for an ongoing conversation with the AI, rather than every interaction starting fresh.
> **翻译**：记忆保存之前的消息历史，让 AI 能持续对话，而不是每次从头开始。

| 记忆方案 | 说明 |
|---------|------|
| **Simple Memory（简单记忆）** | 保存当前会话的一段可配置长度的聊天历史。**新手首选** |
| Redis / Postgres Chat Memory | 用 Redis/Postgres 存会话历史（自部署进阶） |
| Chat Memory Manager | 高级记忆管理（多会话、会话清理） |

> ⚠️ **要点**：只有 **Agent 能用记忆**，Chain 不能用。想让机器人「记得你刚才说了啥」，用 Agent + Simple Memory。

## 4. 工具 / Tools

> **官方原文**：Tools act like addons that your AI can use to access extra context or resources.
> **翻译**：工具是 AI 可以调用的「外挂」，用来获取额外信息或资源。

n8n 提供的三把「利器」：

| 工具 | 用途 |
|------|------|
| **Call n8n Workflow Tool** | 把**任意 n8n 工作流**变成工具——查数据库、发邮件都能被 AI 调用 |
| **Custom Code Tool** | 写一段代码让 Agent 运行 |
| **HTTP Request Tool** | 让 Agent 自己请求网站/API |

加上现成的 Wikipedia、SerpAPI、向量库检索等工具。**给工具写清楚描述**很重要——Agent 靠描述决定什么时候用它。

> 💡 更高级：`$fromAI()` 函数可以让 **AI 动态决定工具参数**（官方 `ai-examples/use-ai-for-parameters.md`）。

## 5. RAG：接上你的知识库 / RAG & Vector Stores

> **官方原文**：RAG is a technique that improves AI responses by combining language models with external data sources. RAG systems retrieve relevant documents to ground responses in up-to-date, domain-specific, or proprietary knowledge.
> **翻译**：RAG（检索增强生成）把大模型和外部数据源结合，让回答基于最新/领域专属/私有的知识——而不是只靠模型的训练记忆。

**核心流程（两条工作流）**：

```
① 入库：抓取文档 → 切块(Data Loader) → 向量化(Embedding) → 存入向量库(Vector Store)
② 问答：用户提问 → 检索相关片段 → 连同问题一起交给模型 → 给出有依据的回答
```

| 组件 | 节点/概念 | 新手建议 |
|------|----------|---------|
| **向量库（Vector Store）** | Simple Vector Store、Qdrant、Pinecone 等 | 起步用 Simple Vector Store（内存版） |
| **Embedding（向量化模型）** | 把文字变成向量，如 `text-embedding-3-small` | 小模型快且便宜，够用就行 |
| **切块（Data Loader）** | Default Data Loader + 切分器 | 默认配置即可；小文档用 Recursive Character Splitter |
| **检索** | 接成 Agent 的工具，或向量库节点直接 Get Many | Agent 方式更灵活 |

> 💡 **官方模板**：[RAG Starter Template](https://n8n.io/workflows/5010-rag-starter-template-using-simple-vector-stores-form-trigger-and-openai) 包含「上传文件」和「问答」两个现成工作流，导入即用。
>
> **节省成本技巧**：先让「向量检索问答工具（Vector Store Q&A Tool）」把相关资料查出来，再交给贵的模型回答，能省不少 token。

## 6. Chat Trigger：变成聊天机器人 / Chat Trigger

**Chat Trigger（聊天触发器）** 是 AI 工作流的起点，自带一个**可定制的聊天界面**：

- 发布工作流后，会得到一个聊天页面 URL，发给同事/客户就能直接对话。
- 支持 **streaming（流式输出）**：AI 逐字打字（第 07 章提过）。
- 也可以接渠道：Telegram、Slack、Discord 等（把 Chat Trigger 换成对应触发器即可）。

> 💡 **新手第一个 AI 项目**：Chat Trigger → AI Agent（OpenAI/DeepSeek Chat Model + Simple Memory）→ 发布 → 打开聊天页面开聊。**10 分钟搞定。**

## 7. AI 测试与改进 / Test & Improve AI Workflows

> 官方出处：`integrate-ai/test-and-improve-ai-workflows/`

- **为什么 AI 工作流要测试**：大模型有随机性，一次通过不代表次次通过。
- **Quick evaluations（快速评测）**：官方提供现成的评测工作流，批量跑测试问题看回答质量。
- **常见问题修复**：官方 `fix-common-issues.md` 整理了幻觉、格式不对、工具乱用等高频坑及解法。

> 💡 上线前至少跑 10~20 个典型问题，重点看：是否幻觉、是否遵守输出格式、是否在没必要时调用了工具。

## 8. 一句话总结 / TL;DR

```
选型：固定任务用 Chain；要决策/记忆/工具用 Agent
记忆：Agent + Simple Memory = 能记住对话
工具：把工作流/代码/HTTP 变成 AI 的手，描述要写清楚
知识库：RAG = 入库（切块+向量化）+ 问答（检索+生成）
入口：Chat Trigger 自带聊天界面；也能接 Telegram/Slack
模型：OpenAI 不方便就接 DeepSeek / 通义 / Kimi / GLM
```
