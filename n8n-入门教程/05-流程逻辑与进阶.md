## 1. 工作流的组成零件 / Workflow Components

> **官方原文**：This section contains: **Nodes** (integrations and operations), **Connections** (node connectors), **Sticky notes** (document your workflows), **Canvas Groups** (organize related nodes).
> **翻译**：本部分包含：**节点**（集成和操作）、**连接**（节点连接器）、**便利贴**（记录说明）、**画布分组**（整理相关节点）。

| 零件 | 中文 | 作用 | 新手用法 |
|------|------|------|---------|
| **Node** | 节点 | 做一件具体的事 | 核心零件，第 03 章已用过 |
| **Connection** | 连接线 | 节点之间传数据 | 从节点右侧圆点拖到下一个节点左侧 |
| **Sticky Note** | 便利贴 | 在画布上写说明 | 复杂工作流必备：写清楚「这一步干嘛的」 |
| **Canvas Group** | 画布分组 | 把相关节点框在一起 | 节点多了以后整理用，让画布一目了然 |

> 💡 **小白建议**：工作流超过 4~5 个节点时，养成「加便利贴 + 分组」的习惯，一周后回来看自己还能看懂。

## 2. 流程逻辑四大基本形态 / Core Flow Logic

> **官方原文**：n8n allows you to represent complex logic in your workflows.
> **翻译**：n8n 允许你在工作流中表达复杂逻辑。

### 2.1 分支 / Split: If & Switch

| 节点 | 中文名 | 用途 |
|------|--------|------|
| **If** | 如果判断 | 条件成立走「真 true」，不成立走「假 false」——第 03 章用过 |
| **Switch** | 多路分支 | 按多个条件把数据分到多个分支（如按城市分：上海/北京/其他） |

```
If / Switch 示意图：
        输入
         │
   ┌─────┴─────┐
  分支1   分支2   分支3…
```

### 2.2 合并 / Merge

| 节点 | 中文名 | 用途 |
|------|--------|------|
| **Merge** | 合并 | 把两个分支的数据合并成一组 |
| **Compare Datasets** | 数据集对比 | 对比两组数据找出差异（如：上周和这周的客户列表） |
| **Code** | 代码 | 写 JS 自定义处理（进阶） |

### 2.3 循环 / Loop

- **Loop Over Items（逐条处理）**：对一批数据逐条执行同一个操作。
  - 例：抓回来 100 条新闻，逐条发送到 Telegram 群。
- **官方核心节点**：`Split In Batches`（分批）等。

> 官方原文：Nodes process multiple items automatically. When a node receives an array of data items, it processes each item individually.
> 翻译：节点会自动处理多条数据项。当节点收到一组数据时，会逐条执行配置好的操作。
> 💡 也就是说：**很多「循环」其实是自动的**——直接连过去，下游节点默认就会逐条处理。只有需要「每条等一会儿」「控制批量大小」时才用专门的循环节点。

### 2.4 等待 / Wait

- **Wait 节点**：让工作流暂停一段时间（比如等 5 分钟再继续），或等到某个具体时间点，或等待用户回复。
- 典型场景：发提醒邮件后等待 24 小时，没回复就发第二次提醒。

## 3. 错误处理 / Handle Errors Gracefully

工作流出错是家常便饭，官方推荐的做法：

| 组件 | 用途 |
|------|------|
| **Stop And Error** | 主动停止并抛出错误信息 |
| **Error Trigger** | 错误触发器：工作流出错时，**触发另一个工作流**来处理错误（发通知、记录日志等） |

> 💡 **小白提示**：新手阶段先把「错误通知」做起来——接一个 Telegram/Gmail 节点，任何工作流出错都通知你，比每天自己刷日志省心得多。

## 4. 子工作流：拆大化小 / Sub-workflows

> 官方出处：`docs/build/flow-logic/convert-to-sub-workflows.md`、`break-workflows-into-smaller-parts.md`

- **Execute Workflow 节点**：在工作流里调用另一个工作流（子工作流）。
- **Execute Workflow Trigger**：作为子工作流的「入口触发器」，接收调用。
- 好处：主工作流清爽、逻辑复用（同一个子工作流能被多个工作流调用）。

```
主工作流：
 [定时触发] → [抓数据] → [Execute Workflow 调用"发报告"子工作流]
                                    │
子工作流 "发报告"：              [Execute Workflow Trigger] → [整理数据] → [发邮件]
```

> 💡 **小白建议**：前 10 个工作流不用拆，一个流程一张图即可。等出现「同样的逻辑要在多个工作流里用」时，再学拆子工作流。

## 5. 数据操作常用节点清单 / Handy Node Cheat Sheet

| 场景 | 推荐节点 | 说明 |
|------|---------|------|
| 定时执行 | Schedule Trigger | 按分钟/小时/天/周/月触发 |
| 接收外部请求 | Webhook | 别人 POST 数据到你的 URL |
| 抓取网页/API | HTTP Request | 万能请求节点（第 03 章替代方案用过） |
| 转换/整理数据 | Edit Fields (Set) | 官方推荐的数据整理节点（第 04 章讲过） |
| 筛选数据 | Filter | 只保留满足条件的数据 |
| 去重 | Remove Duplicates | 删除重复数据 |
| 排序 | Sort | 按字段排序 |
| 聚合 | Aggregate | 把多条数据合并成一条 |
| 发邮件 | Gmail / Email (IMAP/SMTP) | 邮件通知 |
| 即时通讯 | Telegram / Slack / 企业微信 / 钉钉 | 消息通知 |
| AI 对话 | AI Agent | 对接大模型做智能任务 |

> 💡 **小白提示**：这些节点不用记！在画布搜索框输入中文/英文关键词（如「去重」「telegram」）就能找到。记「有这个功能、大概叫啥」就够了。
