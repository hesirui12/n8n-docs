## 1. 多分支的执行顺序 / Execution Order

> 官方出处：`docs/build/flow-logic/understand-execution-order.md`

两条分支并行时，n8n 谁先跑？

| 版本 | 规则 |
|------|------|
| **v1（推荐，新工作流默认）** | **整条分支跑完再跑下一条**。按画布位置：从上到下；同高度则从左到右 |
| **v0（旧版）** | 每条分支先跑第一个节点，再跑第二个……「逐层推进」 |

可以在**工作流设置**里切换。对「各分支互相独立」的场景两者没区别；如果分支之间有数据依赖，v1 更符合直觉。

## 2. 分支 / Split: If & Switch

> 官方出处：`docs/build/flow-logic/split-with-conditionals.md`

| 节点 | 用途 |
|------|------|
| **If（如果）** | 一个条件：成立走 true，不成立走 false（第 03 章用过） |
| **Switch（多路分支）** | 多个条件/多值路由：按城市、按状态、按金额区间分到不同分支 |

```
If / Switch 示意图：
        输入
         │
   ┌─────┴─────┐
  分支1   分支2   分支3…
```

> 💡 Switch 支持范围判断（如金额 `>1000` / `100~1000` / `<100`）和「Fallback（兜底）」分支，处理多分类时比一堆 If 清爽得多。

## 3. 循环 / Loop（深入版）

### 3.1 自动循环：大多数时候你不需要建循环

> **官方原文**：n8n handles this repetitive processing automatically, meaning you don't need to specifically build loops into your workflows.
> **翻译**：n8n 会自动处理重复处理，你不需要专门在流程里搭循环。

- 上游来 5 条客户数据 → 下游 Slack 节点**自动发 5 条消息**，逐条处理。
- 想「只处理第一条」：在该节点 Settings 里开 **Execute Once**（第 05 章讲过）。

### 3.2 需要手动建循环的场景 / Node Exceptions

个别节点**不会自动逐条处理**，必须自己设计循环：

| 节点 | 注意 |
|------|------|
| **HTTP Request** | 分页要自己处理：一页一页抓（用循环） |
| **Code 节点**（Run Once for All Items 模式） | 自己写循环处理全部数据 |
| **Execute Workflow**（Run Once for All Items 模式） | 同上 |
| **RSS Read** | 对同一个 URL 只执行一次 |
| 数据库类（MongoDB、SQL 等 insert/update） | 只执行一次 |

### 3.3 两种循环结构

**循环直到条件满足**：把某个节点的输出接回前面的节点，用 **If** 判断何时停止。

**逐条/分批处理完所有数据**：用 **Loop Over Items（逐条循环）** 节点。

- **Batch Size = 1**：每条单独处理（比如逐条发消息）
- **Batch Size > 1**：按批处理——**避免 API 限流**的好办法（比如每 50 条一批）

> 💡 Loop Over Items 自带有停止逻辑（处理完自动停），不用额外加 If。

## 4. 合并 / Merge

> 官方出处：`docs/build/flow-logic/merge-data.md`

| 节点 | 用途 |
|------|------|
| **Merge** | 把两条（或多条）数据流合并成一组。分支后的「汇合」靠它 |
| **Code** | 复杂场景下合并多个节点的多次执行结果 |
| **Compare Datasets** | 先比较再合并：输出最多 4 条流（新增的、保留的、删除的、相同的），比如对比上周/本周客户名单 |

**Merge 节点常用模式**（官方文档列出的几种）：

- **Append（追加）**：两组数据首尾相连
- **Keep existing / Keep new**：只保留其中一组（去重思路）
- **Combine by field（按字段连接）**：像 SQL JOIN 一样按关键字段关联

> 💡 模板示例：官方有现成的 [joining-different-datasets 示例工作流](https://n8n.io/workflows/1747-joining-different-datasets/)（`docs/_workflows` 里也有 JSON）。

## 5. 等待 / Wait

> 官方出处：`docs/build/flow-logic/wait.md`

**Wait（等待）节点**让工作流暂停：

| 等待方式 | 场景 |
|---------|------|
| 固定时长（等 5 分钟） | 给外部系统处理时间 |
| 等到某个具体时间点 | 每天下午 3 点再跑 |
| 等待用户回复（配合 Webhook） | 发提醒邮件后等 24 小时，没回复就发第二封 |

> 💡 注意：等待中的执行会显示为 **Waiting** 状态，同样会占用执行配额（按触发计费）。

## 6. 错误处理 / Handle Errors Gracefully

> 官方出处：`docs/build/flow-logic/handle-errors-gracefully.md`

### 6.1 错误工作流（Error Workflow）

每个工作流都可以在 **Workflow Settings** 里指定一个「错误工作流」：当本工作流执行失败时，自动运行它来处理错误（发通知、记日志）。

- 错误工作流必须以 **Error Trigger（错误触发器）** 开头。
- **同一个错误工作流可以给多个工作流共用**——搭一个「失败通知」，全公司的工作流都指向它。

### 6.2 主动制造失败：Stop And Error

**Stop And Error（停止并报错）节点**：在特定条件下主动让工作流失败，从而触发错误工作流。比如「订单金额小于 0 就报错」。

### 6.3 节点级错误策略

单个节点的 **Settings → On Error**（第 05 章讲过）：Stop Workflow / Continue / Continue (using error output)。

> 💡 **新手基建建议**：搭一个「错误通知工作流」（Error Trigger → Telegram/Gmail 通知），然后给自己所有生产工作流都配上。比每天自己刷日志省心得多。

## 7. 子工作流 / Sub-workflows

> 官方出处：`docs/build/flow-logic/break-workflows-into-smaller-parts.md`、`convert-to-sub-workflows.md`

### 7.1 两个关键节点

| 节点 | 角色 |
|------|------|
| **Execute Workflow（执行工作流）** | 主工作流里调用别的（子）工作流 |
| **Execute Workflow Trigger（子工作流触发器）** | 子工作流自己的「入口」，接收调用 |

```
主工作流：
 [定时触发] → [抓数据] → [Execute Workflow 调用"发报告"子工作流]
                                    │
子工作流 "发报告"：              [Execute Workflow Trigger] → [整理数据] → [发邮件]
```

**好处**：主流程清爽、逻辑复用（同一个子工作流能被多个工作流调用）。

> 💡 **官方提示**：子工作流执行**不计入配额**（只有顶层工作流计一次）——把低频但耗时的逻辑拆成子工作流还能省配额。

### 7.2 一键转换：Convert to Sub-workflow

n8n 1.97+ 支持**选中一段节点 → 右键 → Convert to sub-workflow（转换为子工作流）**，自动完成重构：

- 被选中节点不能包含触发器
- 外部只允许**一个输入节点 + 一个输出节点**（不能选 If 这种两头出）
- 涉及其他节点引用会**自动更新表达式**并转成参数传入

> 💡 前 10 个工作流不用拆，一个流程一张图即可。出现「同样的逻辑要在多个工作流里用」时再学拆。

## 8. 常用数据节点清单 / Handy Node Cheat Sheet

| 场景 | 推荐节点 | 说明 |
|------|---------|------|
| 定时执行 | Schedule Trigger | 按分钟/小时/天/周/月触发 |
| 接收外部请求 | Webhook | 别人 POST 数据到你的 URL |
| 抓取网页/API | HTTP Request | 万能请求节点（第 03 章替代方案用过） |
| 转换/整理数据 | Edit Fields (Set) | 官方推荐的数据整理节点（第 04 章讲过） |
| 筛选数据 | Filter | 只保留满足条件的数据 |
| 去重 | Remove Duplicates | 删除重复数据 |
| 排序 | Sort | 按字段排序 |
| 聚合 | Aggregate / Summarize | 把多条数据合并成一条 / 类似 Excel 透视表 |
| 发邮件 | Gmail / Email (IMAP/SMTP) | 邮件通知 |
| 即时通讯 | Telegram / Slack / 企业微信 / 钉钉 | 消息通知 |
| AI 对话 | AI Agent / Chat Trigger | 对接大模型做智能任务（第 12 章） |

> 💡 **小白提示**：这些节点不用记！在画布搜索框输入中文/英文关键词（如「去重」「telegram」）就能找到。记「有这个功能、大概叫啥」就够了。

---

## 9. 一句话总结 / TL;DR

- 分支用 If/Switch，汇合用 Merge，等待用 Wait
- **大多数循环是自动的**；只有 HTTP 分页、Code 节点等少数情况要手搭循环
- 错误处理 = 错误工作流（Error Trigger）+ 节点 On Error 策略 + Stop And Error
- 重复逻辑拆子工作流，右键一键转换
- 多分支执行顺序可以在工作流设置里调 v1/v0
