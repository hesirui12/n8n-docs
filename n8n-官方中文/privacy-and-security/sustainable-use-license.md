# 可持续使用许可证

{% hint style="info" %}
**企业版专有许可证**

企业客户可以使用专有许可证（proprietary license）。如需了解更多信息，请[联系我们](mailto:license@n8n.io)。
{% endhint %}

{% hint style="info" %}
**小白必读：这一页在讲什么？**

"许可证"（license）就是一份说明"你可以怎么用这个软件"的授权文件。这一页详细解释 n8n 的 **Sustainable Use License（可持续使用许可证）**：哪些用法被允许、哪些不被允许、为什么 n8n 不叫自己"开源软件"等等。**如果你打算在商业产品里使用 n8n，请务必仔细读完这一页。**
{% endhint %}

n8n 的[可持续使用许可证](https://github.com/n8n-io/n8n/blob/master/LICENSE.md)和[n8n 企业许可证](https://github.com/n8n-io/n8n/blob/master/LICENSE_EE.md)都基于 [fair-code](https://faircode.io/)（公平代码）模式。

{% hint style="info" %}
**小白必读：什么是 fair-code？**

fair-code（公平代码）不是一种具体的许可证，而是一种"软件授权理念"：软件**免费可用**、**源码公开可看**、**允许任何人扩展**，但**作者保留商业使用限制**——也就是"代码给你看、给你改，但你不能拿它直接卖钱"。稍后本页会详细解释。
{% endhint %}

## 许可证常见问题（FAQ）

### 你们用的是什么许可证？

n8n 使用[可持续使用许可证](https://github.com/n8n-io/n8n/blob/master/LICENSE.md)和[n8n 企业许可证](https://github.com/n8n-io/n8n/blob/master/LICENSE_EE.md)。这些许可证都基于 [fair-code](https://faircode.io/) 模式。

### 可持续使用许可证覆盖哪些源代码？

[可持续使用许可证](https://github.com/n8n-io/n8n/blob/master/LICENSE.md)适用于我们在[主 GitHub 仓库](https://github.com/n8n-io/n8n)中托管的**所有**源代码，但以下情况除外：

* 非 master 分支的内容。
* 文件名中包含 `.ee.` 的源代码文件。这些文件使用 [n8n 企业许可证](https://github.com/n8n-io/n8n/blob/master/LICENSE_EE.md)授权。

{% hint style="info" %}
**小白必读：`.ee.` 是什么？**

`.ee.` 是 "Enterprise Edition"（企业版）的缩写。凡是文件名里带 `.ee.` 的代码（例如 `some-node.ee.ts`），都属于企业版功能，不在免费许可证范围内，需要购买企业版许可证才能使用。
{% endhint %}

### 什么是可持续使用许可证？

可持续使用许可证是 n8n 于 2022 年创建的一种 fair-code 软件许可证。你可以[在此](#你们为什么创建许可证)阅读更多关于我们为何这样做的内容。该许可证授予你免费使用、修改、创作衍生作品和再分发的权利，但有**三项限制**：

* 你只能将软件用于**自己的内部业务用途**，或用于**非商业/个人用途**。
* 你只有在**免费**且用于**非商业目的**的前提下，才能向他人分发或提供该软件。
* 你不得修改、删除或隐藏软件中许可方的任何许可、版权或其他声明。对许可方商标的任何使用均须遵守适用法律。

我们鼓励任何想使用可持续使用许可证的人使用它。如果你正在公开环境中构建东西，尽早考虑许可问题是有意义的，这样可以避免日后出现问题。如果你想咨询相关问题，请通过 [license@n8n.io](mailto:license@n8n.io) 联系我们。

{% hint style="info" %}
**小白必读：用大白话总结三项限制**

1. 自己公司内部用、做点个人项目——**可以**。
2. 想拿去卖钱、做成商业服务收费——**不行**。
3. 代码里的版权声明不能删——**必须保留**。

这三点就是"可持续使用许可证"和"彻底开源"之间的核心区别。
{% endhint %}

### 在 n8n 产品语境下，许可证允许什么、不允许什么？

我们的许可证把用途限制为"**内部业务用途**"。实际上这意味着：除非你在销售一个**价值完全或主要来源于 n8n 功能**的产品、服务或模块，否则所有用途都是允许的。下面是一些**不允许**的例子：

* 把 n8n 白标化（换皮改名）后收费提供给客户。
* 托管 n8n 并向用户收费访问。

{% hint style="info" %}
**小白必读：什么是"白标化"（white-labeling）？**

白标化就是把一个现成产品"贴牌"成自己的产品——把 n8n 的 logo、名字换成你自己的，然后包装成"你的产品"卖给别人。这类行为价值几乎全部来自 n8n 本身，所以是许可证明令禁止的。
{% endhint %}

以下所有例子在我们的许可证下都是**允许**的：

* 使用 n8n 同步你公司控制的数据，例如把 CRM 的数据同步到内部数据库。
* 为你的产品创建一个 n8n 节点，或创建任何其他你的产品与 n8n 之间的集成。
* 提供与 n8n 相关的咨询服务，例如构建工作流、开发与 n8n 紧密相关的自定义功能，或编写由 n8n 执行的代码。
* 为 n8n 提供支持服务，例如在公司内部服务器上安装或维护 n8n。

{% hint style="info" %}
**小白总结：什么能卖、什么不能卖？**

- **能卖**：你的"服务"和"专业知识"——比如帮客户搭工作流、写集成、做咨询，这些收费没问题。
- **不能卖**：把"n8n 本身"当成商品——比如托管 n8n 收访问费、换皮后卖给别人。判断标准就一句话：**客户付钱买的是"n8n 本身的能力"，还是"你提供的服务/产品"？** 前者不行，后者可以。
{% endhint %}

#### 我可以用 n8n 作为后端来为我的应用提供某个功能吗？

通常是可以的，只要后端流程**不使用用户自己的凭据**去访问他们的数据。

这里举两个例子来说明：

##### 示例 1：把 ACME 应用与 HubSpot 同步

Bob 搭建了 n8n，用来收集用户的 HubSpot 凭据，将 ACME 应用中的数据与 HubSpot 中的数据进行同步。

<span style="color: #BF2F51;">**不允许**</span>（在可持续使用许可证下）。这个用例收集了用户自己的 HubSpot 凭据来拉取信息并输入到 ACME 应用中。

{% hint style="info" %}
**为什么这个例子不行？**

关键问题在于：用户把自己的 HubSpot 账号凭据交给了"别人的产品"（ACME 应用），由 ACME 代管并使用这些凭据。这种"收集用户个人账号凭据来喂养你自己的产品"的做法，正是许可证禁止的——因为它本质上是在用 n8n 帮你的产品获得用户的私人数据访问权。
{% endhint %}

##### 示例 2：在 ACME 应用中嵌入 AI 聊天机器人

Bob 搭建了 n8n，在 ACME 应用内嵌了一个 AI 聊天机器人。n8n 中该 AI 机器人的凭据使用的是 **Bob 公司的凭据**。ACME 应用的终端用户只需要向聊天机器人输入他们的问题即可。

<span style="color: #1C9985;">**允许**</span>（在可持续使用许可证下）。没有收集任何用户凭据。

{% hint style="info" %}
**为什么这个例子可以？**

这里 AI 机器人使用的凭据是 Bob 自己公司的，用户没有交出任何个人账号凭据。n8n 只是在后端替你干活，用户输入的只是普通的问题文本。没有"拿用户私人凭据"这件事，所以完全没问题。
{% endhint %}

### 如果我想把 n8n 用于许可证不允许的用途怎么办？

你必须与我们签订一份单独的商业协议。我们非常鼓励软件创作者在自己的产品中基于 n8n 构建；我们只是要求他们签署一份协议，写明使用条款以及因以这种方式使用产品而应付给 n8n 的费用。[联系我们](mailto:license@n8n.io)了解更多信息。

如果你不确定自己设想中的用例是否属于"内部业务用途"，请先看看[上面这些例子](#在-n8n-产品语境下许可证允许什么不允许什么)；如果仍然不清楚，请发邮件至 [license@n8n.io](mailto:license@n8n.io)。

### 你们为什么不用开源许可证？

n8n 的使命是给每个使用电脑的人赋予"技术超能力"。我们认为实现这一使命的最佳方式是：让 n8n 对用户尽可能广泛、免费地可用，同时确保我们能建立一个可持续、可发展的商业。通过让产品免费使用、易于分发、源码公开（source-available），我们帮助每个人获得产品；通过以商业方式运营，我们才能长期持续地发布新功能、修复 bug、提供可靠的大规模软件。

### 你们为什么创建许可证？

创建许可证是我们最不喜欢的选项。我们是在审视了现有的各种许可证、发现没有一种完全符合我们的特殊需求之后，才走上这条路的。为了减轻使用专有许可证带来的痛苦和摩擦，我们做了两件事：

1. 用简单直白的英语撰写，并且尽量简短。
2. 推广 [fair-code](https://faircode.io/)，目标是让它成为描述我们这类软件模式的知名总称。

我们创建可持续使用许可证时的目标是：

1. 尽可能宽松（permissive）。
2. 保障我们建立业务的能力。
3. 尽可能清楚地说明哪些用途被允许、哪些不允许。

### 我们公司有"禁止使用限制商业用途的代码"的政策，我还能用 n8n 吗？

只要你把 n8n 用于**内部业务用途**，并且**没有**把 n8n 提供给客户让他们连接自己的账号、构建工作流，那你就可以使用 n8n。如果你不确定自己设想中的用例是否属于"内部业务用途"，请先看看[上面这些例子](#在-n8n-产品语境下许可证允许什么不允许什么)；如果仍然不清楚，请发邮件至 [license@n8n.io](mailto:license@n8n.io)。

{% hint style="info" %}
**小白解读：一句话回答**

"限制商业使用"和"你自己内部做生意用它"是两回事。政策禁止的是"把 n8n 当作商业产品的一部分卖出去"，而你公司内部拿 n8n 优化自己的业务流程，并不违反政策。判断关键还是那条老标准：**有没有让客户直接使用 n8n？**
{% endhint %}

### 在可持续使用许可证下，我贡献给 n8n 的代码会怎样？

你在 GitHub 上贡献的任何代码都受 GitHub 的[服务条款](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#d-user-generated-content)约束。简单来说，这意味着你**拥有**你贡献的内容并**对其负责**，但你同时授予其他 GitHub 用户使用这些代码的某些权利。当你向带有许可证声明的仓库贡献代码时，你就相当于按相同的条款授权了这些代码。

n8n 要求每位贡献者签署我们的[贡献者许可协议（CLA）](https://github.com/n8n-io/n8n/blob/master/CONTRIBUTOR_LICENSE_AGREEMENT.md)。除了上述内容外，这份协议还使 n8n 能够在**无需额外征求许可**的情况下更改其许可证，同时也意味着你**不必**为你的贡献承担责任（例如，万一你的贡献对别人的业务造成了损害）。

开始向 n8n 贡献代码很简单，从[这里](https://github.com/n8n-io)开始；我们也列出了参与社区的各种方式，见[这里](https://app.gitbook.com/s/6OmLnmci5kZDzdkzKREn/contribute-to-n8n)。

{% hint style="info" %}
**小白必读：什么是 CLA？**

CLA（Contributor License Agreement，贡献者许可协议）是开源/源可用项目常见的一份法律文件。你贡献代码前签了它，就相当于明确同意："我的代码交给这个项目使用，项目可以按自己的许可证继续分发"。这让项目方（n8n）日后调整许可证时不用逐个找每个贡献者重新要授权，也保护了贡献者不因代码被使用而承担连带责任。
{% endhint %}

### 你们为什么从之前的许可证安排（带 Commons Clause 的 Apache 2.0）切换到可持续使用许可证？

直到 2022 年 3 月 17 日，n8n 一直使用带 Commons Clause 的 Apache 2.0 许可证。Commons Clause 是由多家软件公司发起的一项条款，目的是保护自己免受云服务商的侵害，思路是在现有开源许可证之上再附加一条商业使用限制。

{% hint style="info" %}
**小白必读：什么是 Apache 2.0 + Commons Clause？**

- **Apache 2.0**：一个非常流行的开源许可证，允许自由使用、修改、分发。
- **Commons Clause（公共条款）**：由一些公司附加在开源许可证之上的额外条款，核心是"你不能把本软件当作商业服务卖钱"（主要防云厂商白嫖）。

两者组合后的效果是：源码能看、能改，但不能拿来商业化销售。问题是这种组合在社区里引发了很多关于"它还算不算开源"的争议，而且条款措辞模糊，容易产生歧义。
{% endhint %}

然而，把 Commons Clause 作为开源许可证的附加条件使用，加上一些措辞容易被不同理解，导致在使用条款上产生了混乱和不确定性。Commons Clause 还限制了人们提供咨询和支持服务的能力：我们意识到这些服务对帮助人们从 n8n 中获得价值至关重要，所以我们想取消这个限制。

我们创建可持续使用许可证，是为了让许可**更宽松**、对允许的用途**更明确**，同时继续确保 n8n 获得建设和改进产品所需的资金。

### 可持续使用许可证和之前的许可证安排（带 Commons Clause 的 Apache 2.0）之间主要区别是什么？

可持续使用许可证与之前的许可证安排之间有两大区别。第一，我们**收紧了软件使用方式的定义**：以前 Commons Clause 限制的是用户"销售"软件；我们把它重新定义为限制"仅限内部业务用途"。第二，以前的许可证限制了人们为软件相关咨询或支持服务收费的能力：我们**完全取消了这一限制**。

这意味着你现在可以自由提供商业咨询或支持服务（例如构建 n8n 工作流），而无需与我们另行签订许可证协议。如果你有兴趣加入我们提供这些服务的 n8n 专家社区，可以在这里了解更多。

{% hint style="info" %}
**小白总结：两大区别**

1. "不许卖" → 改成"只许内部用"（定义更清晰，堵住"变相卖"的漏洞）。
2. "咨询/支持不能收费" → 改成"随便收"（鼓励生态里出现专业的 n8n 服务商）。
{% endhint %}

### n8n 是开源的吗？

虽然 n8n 的源代码在可持续使用许可证下可用，但根据[开放源代码促进会（OSI）](https://opensource.org/)的定义，开源许可证**不能包含使用限制**，所以我们不把自己称为开源。实际上，n8n 为大多数用户提供了与 OSI 认可的开源软件许多相同的益处。

我们创造了 ['fair-code'](https://faircode.io/) 这个词，用来描述我们的许可模式，以及那些"源码公开（source-available）但限制源代码商业使用"的其他公司的模式。

{% hint style="info" %}
**小白必读：开源 vs 源可用（source-available）**

- **开源（Open Source）**：OSI 认证的许可证，要求允许任何人在任何场景（包括商业）使用，不能加限制。
- **源可用（Source-available）**：源码公开给你看、给你改，但可以附加使用限制（比如 n8n 的"仅限内部业务用途"）。

n8n 属于后者。所以严格来说，n8n 不能自称"开源"，而是"源可用 + fair-code"。对绝大多数用户来说，日常使用体验和开源软件几乎没区别——区别只体现在"能不能拿 n8n 本身卖钱"这件事上。
{% endhint %}

### 什么是 fair-code？可持续使用许可证和它是什么关系？

Fair-code 不是一种软件许可证。它描述的是一种软件模式，在这种模式下软件：

* 通常可以免费使用，任何人都可以分发。
* 源码公开可用。
* 任何人都可以在公开和私密社区中扩展。
* 其作者对其施加商业限制。

可持续使用许可证就是一种 fair-code 许可证。你可以在[这里](https://faircode.io/)了解更多并查看其他 fair-code 许可证的例子。

我们总是乐于与感兴趣的人讨论软件许可证、fair-code 以及围绕代码共享的其他原则。想聊一聊的话，请发邮件至 [license@n8n.io](mailto:license@n8n.io)。

可以！我们很高兴看到更多软件使用可持续使用许可证。如果你正在使用我们的许可证，我们很乐意了解你的项目：[license@n8n.io](mailto:license@n8n.io)。
