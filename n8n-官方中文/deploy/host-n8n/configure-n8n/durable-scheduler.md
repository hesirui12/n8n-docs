# 持久化调度器（Durable scheduler）

持久化调度器（durable scheduler）从「数据库队列」运行基于时间的工作流（例如以「定时触发节点」Schedule Trigger node 开头的工作流），而不是从每个实例的内存中运行。本页解释持久化调度器改变了什么、如何开启它，以及它的工作原理。配置它的环境变量请参见 [调度器环境变量（Scheduler environment variables）](basic-configuration/use-environment-variables/scheduler.md)。

{% hint style="warning" %}
**预览功能（Preview feature）**

持久化调度器是一个由环境变量开关控制的预览功能。在它正式发布（general availability）之前，相关的环境变量和默认行为可能会发生变化。
{% endhint %}

{% hint style="info" %}
持久化调度器默认关闭，并正在逐步推广中。现有的实例会继续使用内存调度器，行为与之前完全一致，直到你主动选择开启。n8n 建议先在一个非生产环境中测试它。
{% endhint %}

{% hint style="info" %}
**小白提示**：调度器（scheduler）就是负责「到点自动运行定时工作流」的组件。传统上 n8n 把「下次该几点运行」这个计时信息放在内存（内存 = 服务器运行时暂时存放数据的地方）里；而持久化调度器把它存进数据库。好处是：服务器重启了定时任务不会丢；多台服务器一起跑时也不会重复执行。下文会详细解释。
{% endhint %}

## 内存调度器 vs 持久化调度器（In-memory scheduler compared to the durable scheduler）

默认情况下，n8n 在内存中调度基于时间的工作流。每个主实例（main instance）自己计算出它的活动调度（active schedules）应该在什么时候触发，并在自己的进程内保存这些定时器。这对于单个实例来说工作得很好，但它有局限：

- **重启会丢失待执行的任务。** 当实例停止时，它内存中的定时器也随之消失。对于停机期间已经错过触发时间的任务，n8n 会直接跳过，而不是补跑。
- **多实例需要一个「领导者」。** 在多主（multi-main）架构中，只有「领导者」实例负责触发调度。如果领导权在错误的时机发生切换，时间安排就可能出现偏差。

持久化调度器通过把调度工作移入数据库来解决这两个问题：

- **重启后任务仍然存在。** 调度器会在每个即将执行的任务到期之前，把它记录到数据库中。重启不会丢失它。如果某个任务在实例停机期间错过了触发时间，它仍会在实例恢复后运行——也就是说「会晚点跑」，但不会「不跑」。
- **每个任务在多个实例间只执行一次。** 每个主实例共享同一个队列，并从队列中认领（claim）任务。每个任务只会被一个实例取走，所以工作会分散到你的各个主实例上，而不是依赖单一的领导者。

### 功能上有什么变化（What changes functionally）

开启持久化调度器后，请注意以下行为变化：

- **定时精度。** 调度器会按一个较短的间隔检查到期的任务（`N8N_SCHEDULER_EXECUTOR_INTERVAL`，默认 5 秒），所以一个任务最多可能比预定时间晚一个间隔才开始。而内存调度器的触发时间更接近精确时刻。
- **默认保持「对齐时钟」的定时方式。** 对于「每 N 秒」和「每 N 分钟」的调度，除非你修改 `N8N_SCHEDULER_TRIGGER_NODE_MODE`，否则持久化调度器会保持与内存调度器相同的「对齐时钟」定时方式。参见 [定时触发节点的定时方式（Schedule Trigger timing）](#trigger-node-mode)。
- **停机后的补跑。** 因为调度器会提前记录任务，停机期间错过的任务会在实例恢复时触发，而不是被丢弃。

## 开启持久化调度器（Turn on the durable scheduler）

将 `N8N_SCHEDULER_ENABLED` 设为 `true` 即可开启。

{% hint style="warning" %}
持久化调度器只有在「工作流发布服务」（workflow publication service）也开启时，才会接管定时触发节点。请同时把 `N8N_SCHEDULER_ENABLED` 和 `N8N_USE_WORKFLOW_PUBLICATION_SERVICE` 都设为 `true`。如果你只开启了调度器而没有开启发布服务，n8n 会记录一条警告日志，定时触发节点仍会在内存调度器上运行。
{% endhint %}

{% hint style="info" %}
**小白提示**：简单来说，开启持久化调度器需要同时设置两个环境变量：`N8N_SCHEDULER_ENABLED=true` 和 `N8N_USE_WORKFLOW_PUBLICATION_SERVICE=true`。只设一个是不起作用的，n8n 会提示你补上另一个。
{% endhint %}

[其余的环境变量](basic-configuration/use-environment-variables/scheduler.md) 只有在调度器开启后才会生效。默认值适合大多数实例，只有在你想调整定时精度、存储或各实例间的负载时才需要修改它们。除非另有说明，所有时长单位都是秒。

## 持久化调度器的工作原理（How the durable scheduler works）

理解下面这些术语，环境变量会更容易理解：

- **调度（Schedule）**：一条周期性规则，例如定时触发节点的「每 15 分钟」设置。调度器把每条调度存储在数据库中。
- **任务（Run）**：一条调度在某个特定时刻的「一次触发」。调度器会提前把即将到来的任务作为单独的数据行记录下来。

调度器会把每个任务移动经过四个阶段，每个阶段都有自己对应的 [环境变量](basic-configuration/use-environment-variables/scheduler.md)：

1. **物化（Materialization）。** 调度器扫描你的活动调度，并记录即将到来的任务（在「物化窗口」materialization window 内）。这会在任务到期之前就把它们写入数据库。
2. **执行（Execution）。** 调度器检查已经记录、且触发时间已到的任务，认领每一个任务（确保没有其他实例会重复取走它），然后启动工作流。
3. **恢复（Recovery）。** 如果一个实例认领了任务但在完成之前就停止了（例如崩溃），「收割器」（reaper）会释放这个任务，让另一个实例可以接走它。
4. **保留（Retention）。** 调度器会把已完成的任务保留一段时间作为近期历史，然后删除它们，以保持数据表体积小巧。

在多个实例之间，每个主实例都会运行全部四个阶段。认领机制保证了安全性：因为每个任务只会被一个实例认领，所以在所有实例上运行这些循环是在分担负载，而不是重复干活。

## 定时触发节点的定时方式（与内存调度器的差异）（Schedule Trigger timing (deviations)）

在持久化调度器下，大多数定时触发节点的调度方式与内存调度器相同。除了上面提到的实例级变化（停机后补跑、每个任务在多个实例间只执行一次）之外，有两种节奏在特定情况下与内存调度器的触发方式不同：

- **「每 N 秒」和「每 N 分钟」。** `N8N_SCHEDULER_TRIGGER_NODE_MODE` 控制它们的触发方式。这是该设置唯一影响的节奏。
- **「每 N 小时」「每 N 天」「每 N 周」或「每 N 个月」。** 在日常使用中，它们在两种模式下都按以前的方式触发。持久化调度器能比内存调度器更正确处理少数罕见的日历边界情况：闰年、一年中的第 53 周，以及夏令时切换——在这些情况下，内存调度器可能会差一个周期。

`N8N_SCHEDULER_TRIGGER_NODE_MODE` 有两个取值：

- `legacy`（默认）：任务在时钟边界（整点整分等）上触发，与内存调度器相同。「每 30 秒」会在每分钟的 :00 和 :30 触发。这种模式在每分钟开头会重新开始计数，所以如果一个间隔不能整除 60 秒，在分钟边界处会出现一段不均匀的间隔。例如「每 7 秒」会在 :00、:07、:14 一直触发到 :56，然后跳回 :00，出现一个 4 秒的间隔而不是 7 秒。
- `new`：任务按固定的秒数间隔触发，从「你激活工作流的那一刻」开始计数，而不是从时钟边界开始。如果你在 :07 激活，「每 30 秒」会在 :07、:37、:07……这样触发。间隔始终精确等于你设置的间隔，跨分钟边界也一样，所以「每 7 秒」永远不会漂移。

`legacy` 是默认值，所以在持久化调度器推广期间，定时方式保持不变。`new` 是未来计划采用的默认值。

{% hint style="info" %}
`N8N_SCHEDULER_TRIGGER_NODE_MODE` 只影响「每 N 秒」和「每 N 分钟」的调度。其他所有节奏，包括原始的 cron 表达式，在任一取值下都以相同方式触发。
{% endhint %}

{% hint style="info" %}
**小白提示**：如果你只是想把定时工作流从「内存」换成「数据库」以获得更可靠的重启恢复，那直接设置 `N8N_SCHEDULER_ENABLED=true` 和 `N8N_USE_WORKFLOW_PUBLICATION_SERVICE=true` 即可，其余变量保持默认就好。`N8N_SCHEDULER_TRIGGER_NODE_MODE` 只在你需要精确控制「每 N 秒/分钟」这类短间隔的触发时刻时才需要关心。
{% endhint %}
