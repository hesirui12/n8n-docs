10 · 数据转换与常用数据节点

Data Transformation & Common Data Nodes

官方出处：docs/build/work-with-data/transform-data/approaches-for-transforming-data.md、expressions-versus-data-nodes.md、handle-special-data-types/work-with-dates-and-times.md、work-with-files-and-images.md、query-json-data.md、reference-data/use-the-ui-mapper.md

本节目标 / What You'll Learn

  • 数据转换的四种手段怎么选（表达式 / Code / AI Transform / 专用节点）
  • 数据变换节点全家桶：Edit Fields、Filter、Limit、Sort、Aggregate、Split Out、Summarize、Remove Duplicates
  • UI Mapper：可视化映射字段
  • 特殊数据类型实战：日期时间、文件图片、JSON 查询

1. 什么时候需要「转换数据」？/ When to Transform

官方原文：Data transformation in n8n involves modifying, restructuring, or enriching data as it moves through your workflow. This includes changing data formats, filtering or aggregating values, adding computed fields, and converting data structures to work with different nodes. 翻译：数据转换就是在数据流经工作流时对它进行修改、重构或丰富——包括改变格式、筛选/聚合值、添加计算字段、转换结构以适配不同节点。

典型场景：上游 API 返回的字段名和下游系统不一致、需要拼一段完整文字、需要把「列表」拆成「多条」、需要去重……

2. 四种转换手段怎么选 / Choose Your Approach

手段 适合 学习成本
表达式（Expressions） 单个字段的取值/简单加工（第 04 章） ⭐ 低
Code 节点 复杂逻辑、循环、自定义函数（第 11 章） 中（要会一点 JS）
AI Transform 节点 用自然语言让 AI 生成转换代码 低
专用转换节点 常见结构变化（见第 3 节清单） ⭐ 最低，首选

官方最佳实践：能用专用节点和表达式解决，就别上 Code。数据变换节点是「标准件」，别人一看就懂。

表达式里的小技巧 / Advanced Expression Tricks

  • 三元运算符：{{ $json.age >= 18 ? '成年' : '未成年' }}
  • 链式函数：{{ $json.name.trim().toUpperCase() }}
  • IIFE 多行逻辑：{{ (()=>{ ... return x; })() }}（第 11 章给完整例子）

3. 数据变换节点全家桶 / Transformation Node Cheat Sheet

节点 中文名 干什么 例子
Edit Fields (Set) 编辑字段 加字段/改值/删字段/重命名，官方推荐首选 给每条数据加 处理时间 字段
Filter 筛选 只保留满足条件的整条数据 只留价格 > 100 的商品
Limit 限制数量 只取前 N 条 只处理前 10 条
Sort 排序 按字段排序或随机打乱 按金额降序
Remove Duplicates 去重 去掉完全相同的条目 表单重复提交
Aggregate 聚合 把多条合成一条（字段变数组） 100 条新闻合成 1 条 JSON
Split Out 拆分 把数组字段拆成多条 一条订单里的 5 件商品拆成 5 条
Summarize 汇总 像 Excel 透视表一样分组统计 按城市统计销售额、均值

💡 记忆法：数据就是「一堆行」——想删行用 Filter/Limit/去重，想加行用 Split Out，想合并行用 Aggregate/Summarize，想改行内容用 Edit Fields。

4. UI Mapper：可视化映射 / UI Mapper

官方出处：docs/build/work-with-data/reference-data/use-the-ui-mapper.md

UI Mapper（界面映射器） 是某些节点（如 Google Sheets、Notion）里提供的一种可视化字段映射工具：左边列出源字段，右边列出目标字段，用下拉框一一对应，不用写表达式。

💡 遇到「把 A 的数据塞到 B 的字段里」的节点配置，先找找有没有 UI Mapper 选项卡——大多数情况比表达式省事。

5. 特殊数据类型实战 / Working with Special Data Types

5.1 日期与时间 / Dates & Times

官方出处：handle-special-data-types/work-with-dates-and-times.md

n8n 表达式内置 Luxon 日期库，常用操作：

{{ $now }}                    // 当前时间
{{ $now.plus({ days: 1 }) }}  // 明天
{{ $now.minus(7, 'days') }}   // 一周前（第 03 章用过）
{{ $json.日期字段.toFormat('yyyy-MM-dd') }}  // 格式化输出
常用方法 作用
.plus({...}) / .minus(n, 'unit') 加减时间
.toFormat('yyyy-MM-dd HH:mm') 自定义格式
.setZone('Asia/Shanghai') 换时区
.diff(其他时间, 'days') 求间隔

⏰ 本土化提醒：定时触发器的「几点」取决于实例/工作流时区（第 15 章讲配置）。自部署记得设 Asia/Shanghai。

5.2 文件与图片 / Files & Images

官方出处：handle-special-data-types/work-with-files-and-images.md

文件类数据在 n8n 里以 binary（二进制） 数据存在（和 json 平级）：

  • 读文件：Read Binary Files 节点（读本地/服务器文件）
  • 收文件：Webhook 收到的上传文件、表单上传
  • 发文件：Email 附件、Telegram 发图、Google Drive 上传
  • 转格式：Convert to File 节点（把 JSON 转成 CSV/PDF/文本）

💡 新手最常用：Convert to File（转成 CSV） 把工作流结果导出成表格文件 → 邮件发给自己。

5.3 查询复杂 JSON / Query JSON

官方出处：handle-special-data-types/query-json-data.md

嵌套很深的 JSON 用点语法会写得又长又脆，官方推荐 JMESPath 查询语法：

{{ $json.orders[?price > `100`].id }}   // 找出价格>100的订单id（注意反引号包数字）
{{ $json.orders | sort_by(@, &price) | [-1].name }}  // 最贵订单的客户名

💡 用到再学。表达式编辑器的帮助面板里有 JMESPath 快速参考。

6. 数据转换的推荐流程 / Recommended Pipeline

取数 →  Edit Fields 整理字段（改名/补字段/格式化）
    →  Filter 删掉不要的行
    →  Sort 排序 / Remove Duplicates 去重
    →  交给下游（发消息、写表、喂给 AI）

官方最佳实践：不要在多个节点里到处写复杂表达式。先集中用一个 Edit Fields 把数据整干净，后面的节点配置会简单到难以置信。

7. 一句话总结 / TL;DR

  • 转换四选一：专用节点（首选）→ 表达式 → AI Transform → Code
  • 记口诀：加行 Split Out、删行 Filter/Limit、并行 Aggregate/Summarize、改行 Edit Fields
  • 日期用 Luxon 方法；文件在 binary 里；复杂 JSON 用 JMESPath
  • 有 UI Mapper 的节点优先用 UI Mapper
