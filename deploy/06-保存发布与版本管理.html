06 · 保存、发布与版本管理

Save, Publish & Versioning

官方出处：docs/build/understand-workflows/save-and-publish-workflows.md、docs/build/manage-workflows/view-change-history.md

本节目标 / What You'll Learn

  • 自动保存机制：没有保存按钮，也不用手动保存
  • 发布（Publish）到底做什么：定时器、Webhook、App 事件什么时候才生效
  • 发布按钮的 6 种状态怎么看
  • 版本历史（Version History）：回滚、克隆、命名版本
  • 取消发布（Unpublish）
  • 多人协作时的「编辑锁」

⚠️ 这是新版 n8n（1.x 之后）的机制：编辑自动保存 + 手动发布。如果你在网上看到老教程教你「保存按钮 / Activate 开关」，那已经过时了。

1. 自动保存 / How Saving Works

官方原文：Changes save automatically as you edit, typically within 1 to 5 seconds. No manual save button is required. All edits remain in draft until you publish. 翻译：编辑时改动会自动保存（通常 1~5 秒内），不需要手动保存按钮。所有改动在发布前都停留在「草稿」状态。

要点：

  • 编辑画布、改节点参数 → n8n 自动落盘，放心关页面。
  • Ctrl/Cmd + S 不是「保存」，而是打开「命名版本」的弹窗（见第 4 节）。

2. 发布是什么 / How Publishing Works

官方原文：Publishing makes your workflow live and locks it to a specific version. Production executions will use this published version, not your latest edits. 翻译：发布让你的工作流生效，并把它锁定到某个具体版本。生产环境的执行会使用这个已发布版本，而不是你最新的编辑。

发布后才会生效的东西（草稿状态下都不生效）：

项目 说明
Webhook / 表单触发器 使用生产环境 URL（生产地址）
定时器（Schedule） 按你设定的时间自动运行
连接的应用事件 外部 App 的事件能触发这个工作流

💡 小白理解：草稿 = 你在工位上改图纸；发布 = 把图纸送去车间开工。改图纸不会影响车间正在跑的版本。

3. 发布按钮的 6 种状态 / Publish Button States

官方手册列出了发布按钮的几种状态，对照看：

状态 含义 能否发布
初始状态（无改动） 没有可发布的改动 按钮禁用
Ready to publish 有改动、还没发布过 可发布
Published, up to date 已发布且没有新改动 —
Published, has changes 已发布，但你又有新改动没上线 可再发布
Published, invalid 已发布但当前改动无法重新发布（比如没有触发器） 不可发布
Published, error 已发布但最近改动有错误 需先修复

怎么发布：

  1. 点画布顶部的 Publish（发布） 按钮（快捷键 Shift + P）。
  2. 弹窗里可以给这个版本命名 + 写描述（可选）。
  3. 点 Publish，改动即刻上线。生产执行永远指向当前已发布版本。

💡 只改「工作流设置」时 n8n 会自动重新发布，不用你操作。

4. 版本历史 / Version History

什么时候会产生一个新版本：

  • 保存工作流（自动保存每次改动算一版）
  • 恢复了旧版本（恢复前 n8n 会先保存当前版）
  • 从 Git 仓库 Pull（第 14 章）

怎么查看和管理：点画布顶部的「历史」图标，会列出所有版本 + 预览画布。每个版本可以：

操作 说明
Restore version 用这个版本替换当前工作流（不影响生产运行）
Clone to new workflow 基于该版本克隆出一个新工作流
Open in new tab 新标签页打开该版本，方便对比
Download 下载该版本为 JSON 文件
Name version 给版本命名（命名版受保护，不会被自动清理）
Unpublish 从生产中下线该版本

⚠️ 版本历史保留期限：普通用户能看到最近 24 小时的版本；Cloud Pro 用户 5 天；Enterprise 有完整历史。命名过的版本永久保留。

💡 别混淆：「版本历史（Workflow history）」是工作流的修改历史；「执行记录（Executions）」是工作流的运行记录——第 07 章讲后者。

5. 取消发布 / Unpublish

想停掉一个线上工作流（定时器不再跑、Webhook 不再接收），可以取消发布：

  • 从 Publish 按钮旁边的下拉箭头（快捷键 Ctrl/Cmd + U）
  • 或从工作流列表
  • 或从版本历史页

💡 取消发布 ≠ 删除。工作流还在你的列表里，随时可以重新发布。

6. 多人协作的编辑锁 / Collaboration

官方原文：Only one person can edit a workflow at a time. If someone else is currently editing, you see the workflow in read-only mode. 翻译：同一时间只有一个人能编辑工作流。如果别人正在编辑，你会以只读模式打开；对方停止或闲置后，编辑锁释放，你才能接手最新版本。

团队协作要点：

  • 别人在编辑 → 你只读，不能改。
  • 别人编辑完/闲置 → 你可以接管。
  • 接管时拿到的是最新改动（别人已经保存的）。

7. 一句话总结 / TL;DR

编辑 → 自动保存（草稿）→ 点 Publish → 生产生效（锁版本）
                    ↕ 随时可以：回滚版本 / 克隆 / 命名 / 取消发布
  • 测试时不用发布，点 Execute Workflow 手动跑
  • 要「定时自动跑」或「Webhook 生效」才需要发布
  • 改完一定要留意发布按钮状态：是 up to date 还是有 pending changes
