14 · 管理工作流与团队协作

Manage Workflows & Collaborate

官方出处：docs/build/manage-workflows/（configure-workflow-settings、tag-workflows、export-and-import、share-with-others、n8n-packages）、docs/administer/manage-users-and-access/README.md、use-source-control-and-environments/README.md

本节目标 / What You'll Learn

  • 工作流设置（Settings）完整清单
  • 标签（Tags）：给工作流分类
  • 导出/导入：JSON、复制粘贴、CLI、API
  • 分享与权限：谁能看到、谁能改
  • 项目（Projects）、用户与角色（Roles）
  • 源码控制（Source Control）：用 Git 管环境

1. 工作流设置清单 / Workflow Settings

打开方式：画布右上角 三个点菜单（⋯）→ Settings（设置）。

设置 作用 新手建议
Execution order 多分支执行顺序：v1（整支跑完再下一支，推荐）/ v0（逐层推进） 默认 v1 即可
Error Workflow 指定失败时触发的错误工作流（第 08 章） 搭一个共用的
This workflow can be called by 允许哪些工作流调用本工作流 子工作流场景用
Timezone 本工作流时区（影响定时触发器！） 中国用户设 Asia/Shanghai
Save failed/successful production executions 是否保存生产执行记录 线上稳定后可关掉成功的
Save manual executions 是否保存手动执行记录 开发期开着
Save execution progress 保存每节点中间数据（出错可断点续跑，更慢） 默认即可
Timeout Workflow 超时自动取消 防死循环必备
Redact production/manual execution data 执行数据脱敏（第 07 章） 处理敏感数据时开
Estimated time saved 每次执行节省多少分钟（给 Insights 统计用） 可填可不填

⏰ 时区再次强调：不设置时区时，n8n 默认用 EDT（纽约）时间——国内用户定时触发一定记得在实例/工作流设置里改成 Asia/Shanghai。

2. 标签 / Tags

给工作流贴标签，然后按标签筛选：

  1. 打开工作流，点工作流名旁的 + Add tag。
  2. 选已有标签或新建（可加多个）。
  3. 在 Workflows 列表页点 Filters → Tags 筛选。

⚠️ 标签是全局的：你建的标签全实例用户都能用。编辑/删除标签会影响所有人（只有实例所有者能删标签）。

3. 导出与导入 / Export & Import

官方出处：build/manage-workflows/export-and-import.md

n8n 工作流本质是 JSON 文件，所以迁移很简单：

方式 操作 适合
复制粘贴 画布上框选节点 → Ctrl/Cmd+C → 到别处 Ctrl/Cmd+V 最灵活，还能跨工作流复用节点
编辑器菜单 三个点菜单 → Download（导出 JSON）/ Import from File（导入）/ Import from URL（从链接导入） 日常备份/搬运
命令行（CLI） n8n export:workflow / n8n import:workflow（第 16 章） 批量、脚本化
Public API REST API 接口 编程化管理
n8n Packages .n8np 打包格式（Beta，含凭据引用） 跨实例迁移/CI/CD

💡 复制粘贴大法：别人分享给你一段工作流 JSON？直接 Ctrl+C 那段 JSON → 在 n8n 画布 Ctrl+V，粘进去了！这是最快的学习/分享方式。

4. 分享与权限 / Sharing & Permissions

官方出处：build/manage-workflows/share-with-others.md（Cloud 全计划 + Enterprise 自部署可用）

两种共享模型：

模型 怎么分享
Personal 空间 打开工作流 → Share → 添加用户
项目（Project） 把工作流放进项目 → 项目成员自动可见（无需逐个分享）

权限矩阵（Creator 创建者 / Editor 编辑者）：

权限 Creator Editor
查看（只读） ✅ ✅
查看执行 ✅ ✅
更新（含标签） ✅ ✅
运行 ✅ ✅
分享 ✅ ❌
导出 ✅ ✅
删除 ✅ ❌

⚠️ 凭据的最小权限原则（第 09 章再提）：对方没共享凭证时，不能编辑用到该凭证的节点（能看能跑不能改）。

5. 项目、用户与角色 / Projects, Users & Roles

官方出处：docs/administer/manage-users-and-access/

用户角色（实例级）：

角色 权限
Owner（所有者） 一切权限，第一个注册的人是 Owner
Member（成员） 普通用户：用自己的空间 + 被分享的项目
Admin（管理员） Pro/Enterprise 计划才有：管理用户、看全实例工作流

项目（Projects）：把工作流、凭据、变量、数据表分组管理。项目成员按角色（Owner / Admin / Member / Viewer）看到不同内容。

💡 团队用的心法：项目 = 团队共享区。把公共工作流和凭据放进项目，个人草稿留在 Personal 空间。

6. 源码控制与环境（进阶）/ Source Control & Environments

官方出处：docs/administer/use-source-control-and-environments/

n8n（Enterprise/付费计划）支持 Git 源码控制：把 n8n 实例接到 Git 仓库，用分支来管理多个环境：

开发实例 ──push──→ Git 仓库 ←──pull── 生产实例
（feature 分支）    （main 分支）
  • Environments（环境）：dev / staging / prod 各一个 n8n 实例，各自连不同 Git 分支
  • Push/Pull：开发环境改完 push 到 Git，生产环境 pull 下来发布
  • 好处：版本回滚、代码评审（PR）、多人协作规范

💡 这是团队/企业上生产前的「正规军」打法。个人学习阶段跳过，知道有这回事即可。

7. 一句话总结 / TL;DR

设置：时区必设；超时/错误工作流建议配
整理：Tags 标签 + 项目分组
迁移：JSON 复制粘贴最方便；批量用 CLI/API/Packages
协作：个人空间 Share 或放项目；权限记「能看能跑不一定能改」
正规化：Git 源码控制管环境（企业）
